# 声音理解评测设计

## 目标与边界

在现有“语音智能实验台”中增加第五个模型模块“声音理解”，复用已随包安装的 SenseVoice INT8 模型，展示语言、情感和声音事件三个模型原生输出。该功能不增加推理模型，也不使用关键词规则推导情感或事件。SenseVoice 的能力边界是片段级语音属性与预定义声音事件分类；会议摘要、意图分析等开放语义不纳入本功能。

录音模式在最终识别完成后展示本次片段的语种、情感与事件。数据集模式进入独立的“声音理解评测”页，以带真值、可播放的内置音频检验模型效果。页面只计算目标字段准确率：CREMA-D 样本评测情感，VocalSound 样本评测声音事件；辅助字段仅展示，不混入总体指标。

## 数据集协议

首版内置 30 条 16 kHz WAV：

- CREMA-D 18 条：愤怒、厌恶、恐惧、高兴、中性、悲伤各 3 条。只选择原始表演标签与人声多数投票一致、投票一致率高的片段，并尽量使用不同说话人。真值来源为官方 `summaryTable.csv` 的 `VoiceVote`。
- VocalSound 12 条：咳嗽、笑声、喷嚏各 4 条，来自官方 test split，覆盖不同说话人与年龄组。这三类可一一映射到 SenseVoice 的 `Cough`、`Laughter`、`Sneeze`。叹气、吸鼻和清嗓不属于 SenseVoice 当前明确事件集合，不放入准确率。

CREMA-D 使用 ODbL 1.0 / Database Contents License，VocalSound 使用 CC BY-SA 4.0。APP 内提供“数据说明”入口，列明数据来源、许可、样本选择协议与模型限制。所有音频支持单条播放；批量测试按固定顺序运行，结果不写入个人声纹或会议数据。

## 页面结构

Image 2 设计稿保存在 `docs/design/audio-understanding-evaluation-ui.png`。页面采用浅色背景和中等信息密度：

1. 顶部标题“声音理解评测”和模型说明“SenseVoice · 情感与声音事件”。
2. 三张指标卡显示总体、情感、事件的正确数与准确率。未运行时显示占位符，运行中实时更新。
3. “全部 / 情感 / 事件 / 未匹配”筛选条控制证据卡列表。
4. 每条证据卡明确并列显示“真实标签”和“模型输出”，右上角显示等待、运行中、匹配、未匹配或失败。
5. 辅助信息展示模型检测的语种、非目标字段、处理时延和音频时长，不显示模型没有提供的置信度。
6. 卡片提供播放/暂停和进度；页面底部提供“批量运行 30 条”。

加载、空结果、推理失败和播放失败都保留真实状态。批量运行时禁用播放，离开页面会终止 Worker 与播放器，不保留模型会话。

## 数据流与结果映射

评测页读取 rawfile 音频并发送 `sherpa-understanding-test` 请求。Worker 使用专用的 SenseVoice recognizer 解码一次，直接返回 `text`、`lang`、`emotion`、`event`、音频时长和处理耗时。页面通过纯函数完成大小写、装饰标签和同义形式归一化，再与测试规格中的机器标签比较；中文名称只用于展示。

录音链路复用同一结果结构。最终重解码时保留 SenseVoice 元信息，通过现有 `sherpa-asr-final` 响应返回，首页的“声音理解”效果卡展示最近一次结果。若文件识别选择离线 Paraformer，声音理解仍单独调用 SenseVoice，避免把 Paraformer 文本误当成声音理解输出。

## 验收标准

- APP 内能看到并进入第五个“声音理解”模块。
- 30 条内置音频均可播放，真实标签在运行前可见。
- 单条和批量测试均显示模型原生输出及匹配结果。
- 总体、情感和事件统计只基于成功完成的对应目标字段，并单独显示失败数。
- 录音结束后能看到语种、情感和事件；空字段明确显示“未检出”。
- 单元测试覆盖标签归一化、匹配判断、汇总统计和筛选逻辑。
