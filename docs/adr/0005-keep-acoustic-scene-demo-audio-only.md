# ADR-0005：主声音场景 Demo 保持纯音频

## 状态

提案（等待产品确认）

## 背景

当前 HarmonyOS Demo 为了尝试提升地铁与高铁的系统级识别结果，引入了 Location Kit 位置派生速度、ASR 关键词和声音事件的人工规则融合，并声明模糊位置权限。

该实现不属于声学场景模型本身，也没有在带同步传感器真值的来源隔离数据集上完成校准和盲测。主 Demo 的目标是分别展示 ASR、标点、声纹、说话人分离、声音理解和声音场景模型的真实端侧效果。默认融合会混淆单模型指标，并增加与核心目标无关的位置权限、功耗、隐私说明和失败面。

## 决策

主声音场景 Demo 只展示纯音频声学模型输出：

- 不申请或使用位置权限；
- 不使用位置派生速度修改场景概率；
- 不使用 ASR 关键词或声音事件修改场景概率；
- 数据集和录音模式采用相同的纯音频推理口径；
- 多传感器场景融合如需继续研究，必须作为独立、默认关闭的实验功能，单独授权、采数、评测和报告。

在产品确认前，本 ADR 保持“提案”状态，不自动触发代码删除。

## 影响

### 正面影响

- 用户可以直接观察声音场景模型的真实效果。
- 移除与声音 Demo 无直接关系的位置权限弹窗。
- 符合最小权限原则，减少隐私、功耗和生命周期复杂度。
- Mac、固定数据集和手机录音更容易保持一致的评测口径。
- 不会把系统融合成绩误写成声音模型成绩。

### 负面影响

- 不再利用高速移动证据修正部分高铁/地铁混淆。
- 纯音频准确率仍可能显著低于 95%，需要通过数据、任务定义和声学模型本身改进。
- 如果未来重新启用融合，需要重新开发实验入口和配套数据协议。

### 中性影响

- ASR 和声音事件模型仍会独立运行并展示结果，只是不再参与场景分数计算。
- 现有声纹、说话人分离、注册资料和会议数据不受影响。

## 备选方案

### 方案 A：保持融合默认开启

不采用。系统级效果未经真实同步传感器盲测，位置授权也会让用户误解 Demo 的核心用途。

### 方案 B：保留融合但默认关闭

可作为未来研究版过渡方案，但不推荐留在当前主产品路径。它仍会带来权限声明、维护成本和误用风险。

### 方案 C：只移除位置，保留 ASR/声音事件融合

不采用。虽然可以移除定位权限，但跨模型规则仍会混淆“声音场景模型效果”和“系统裁决效果”。

## 风险与缓解

| 风险 | 缓解措施 |
|---|---|
| 纯音频结果看起来变差 | 同时展示概率、错误样本和真实标签，保持诚实口径 |
| 产品仍希望达到系统级 95% | 单独建立多传感器项目，采集同步真值后再评估 |
| 删除权限影响升级 | 使用覆盖安装测试，不卸载、不清除数据，并检查系统权限页 |
| 删除融合造成回归 | 保留提交历史，补齐纯音频 UI、权限和端侧推理自动测试 |
