# 离线识别通路优化（2026-07-29）

本轮只动**离线识别通路**（导入音频 / 按住说话松手后的二次识别），不碰声学模型文件，不碰 NPU 通路——推理仍然全部走 onnxruntime CPU。

## 1. 改了什么

### 1.1 线程数：离线通路吃多核（`StreamingSherpaWorker.ets`）

| 模型 | 之前 | 现在 |
|---|---:|---:|
| streaming paraformer（实时） | 2 | 2（不变） |
| offline paraformer（最终识别） | **1** | 4 |
| SenseVoice（候选/兜底） | 2 | 4 |
| 标点 ct-transformer | **1** | 2 |

离线解码是批处理、不占实时预算，之前反而比流式少一个线程。零精度影响。

### 1.2 分段进度的标点由 O(N²) 降到 O(N)（`TranscriptBuilder.ets`）

进度循环原来每解出一段就对**累计全文**跑一次标点模型：N 段音频 = N 次全量标点，文本长度递增。3 分钟音频（18 段）要在 72 MiB 的 CT-Transformer 上跑 18 次。

现在只对该段**新增的文本**加标点用于进度显示，最终交付文本仍然做且只做一次全量标点——交付结果不变，中间开销从 O(N²) 降到 O(N)。wav 与 m4a 两条进度通路都改了。

### 1.3 模型预热（`warmUpOfflineModels`）

离线模型原来懒加载，第一次松手/第一次导入要额外承担模型加载 + 首帧推理。现在在 `sherpa-asr-ready` 发出**之后**用 0.5 s 静音跑一次预热。

代价：ready 之后 worker 会忙一小段时间（加载 216 MiB int8 模型）。此期间录音不会丢——PCM 消息在队列里排着，预热结束后会被追上处理，只是最初的实时字幕可能滞后。这比把同样的开销压在"松手等结果"时更好。

### 1.4 重采样加抗混叠（`Resampler.ets`）

之前是纯线性插值。48 kHz → 16 kHz 时，**8 kHz 以上的所有分量都会折叠回语音带**：12 kHz 分量原样出现在 4 kHz 上。这在 AISHELL（本来就是 16 kHz，不触发重采样）上完全测不出来，只在用户导入的 44.1/48 kHz 录音上发作。

现在用 Blackman 窗 sinc 核（6 个过零点，查表 + 线性插值），截止频率跟随较低的那个采样率。每输出样本按权重和归一，保证 DC 增益为 1、边界不衰减。

### 1.5 离线分段改由 VAD 驱动（`AudioSegmentation.ets`）

之前：固定 10 s 切段，只在 ±0.6 s 内挪到能量最低的 0.16 s 窗口，再加 ±0.25 s 音频重叠，最后用文本重叠启发式去重。连续说话或有稳态底噪时，"能量最低点"经常落在词中间；paraformer 是非自回归 CIF，词中间切一刀会同时损坏前段尾和后段头。

现在：

- 用工程已有的 silero VAD 扫全段，得到逐窗语音判决；
- ≤0.6 s 的停顿不切（一个小句保持完整），<0.2 s 的孤立片段按噪声丢弃，每段前后留 0.2 s padding；
- 相邻语音段在**间隔 ≤1.5 s 且总长 ≤24 s** 时合并进同一个解码块——给声学模型和标点模型更多上下文；间隔更大的另起一块，长静音因此被跳过，不进入解码；
- 单段超过 24 s 时按等分切分，不留碎片；
- 块与块之间不再需要音频重叠，文本重叠去重启发式随之不再对这条通路生效。

回退路径保留：VAD 不可用、VAD 一句话都没听到、或采样率不是 16 kHz 时，仍走原来的定长+静音点切分（含 0.25 s 重叠和文本去重）。短音频（<20 s）也直接走整段解码，与改动前一致。

m4a 仍用定长块：它是按时间区间逐块 demux 的（native 侧有真 seek），跑 VAD 需要先整文件解码一遍，得不偿失。

### 1.6 说话人分段重打分与主通路模型对齐

`decodeSamplesBestDirectWithPunctuation` 之前先试 SenseVoice（本地基准 6.61% CER），而主通路交付文本用的是 offline paraformer（5.01%）——开启说话人分离会静默换成更弱的模型。现在顺序改为 offline paraformer → SenseVoice → streaming。

## 2. 测试

新增 3 个本地单元测试文件（`entry/src/test/`，已在 `List.test.ets` 注册）：

- `Resampler.test.ets`：同采样率短路、输出长度、DC 增益（含首尾样本）、1 kHz 通带增益 ≈1、**12 kHz 抑制到 <0.25**（这条就是抗混叠回归的锚点）、混合信号中 15 kHz 分量不残留、上采样。
- `AudioSegmentation.test.ets`：VAD 判决 → 语音段（短停顿桥接、噪声片段丢弃、padding 裁剪与再合并、末段裁到真实样本数）；解码块规划（相邻合并、超上限另起、**长静音不合并**、超长段等分、每个语音段都被覆盖、稀疏录音解码量远小于时长）；定长回退分段器对全段无缝铺满。
- `TranscriptBuilder.test.ets`：**每段只标点一次**（直接锁住 O(N²) 回归）、进度文本累加、raw 文本供最终全量标点、重叠去重、appender 改写尾部时降级为只标点本段、空贡献段被忽略。

被测逻辑为此从 worker 里抽到 `entry/src/main/ets/common/` 三个模块，这些模块不引用任何 `@kit` API，所以能在本地单测（非真机）里跑。

**这些测试没有在本机执行过**：仓库里的模型与音频是 git-lfs 指针，且本机没有 DevEco / hvigor / oh_modules。需要在装了 DevEco 的机器上跑 `hvigorw test` 验证。

## 3. 本轮没做的（以及为什么）

- **换更强的声学模型**：`model_selection_aishell100.md` 已量到 FunASR paraformer-large 离线 2.85%，现役 2024-03-09 是 5.01%。要下模型 + 重跑基准，属于独立一轮。注意 2026-07-22 那轮被否决的 `paraformer-zh-int8-2025-10-07`（7.93%）**不是** large，两件事别混。
- **热词**：`hotwords_experiment.md` 已坐实 sherpa-onnx 的 paraformer 工厂不接受 hotwords 且只支持 greedy_search——结构上不可用。要吃热词收益必须换 transducer(Zipformer) 或 Qwen3-ASR/FunASR-Nano。
- **NPU/CANN**：明确不做，推理保持 onnxruntime CPU。`cpp/asr_engine/` 那套 NNRt `.om` 代码本轮未改动，仍未被 ArkTS 侧引用。
- **批量解码**：sherpa-onnx 可能支持一次 decode 多个 stream，能摊薄逐段调用开销；本机没有 oh_modules 无法确认 1.13.3 的 ArkTS 绑定是否暴露该接口，留待验证。
- **松手后的增量二次识别**：目前松手后仍对整段会话重跑一次离线识别。改成"VAD 每切出一句就排队跑离线"能把松手等待降到最后一句，但那是 worker 的异步架构改动，风险与本轮的收敛性不匹配。
- **端侧 CER/RTF 回归、会议集人工标注**：本轮所有判断仍只能靠 Mac + Python 基准。会议场景（本 APP 的真实目标场景）没有标注，1.5 节的收益无法量化，只能靠原理与单测保证不回归。

## 4. 诚实 caveat

本轮改动**没有编译过，也没有跑过任何基准**（本机无 DevEco/hvigor，模型为 LFS 指针）。1.1–1.3 是纯性能改动，理论上不影响 CER；1.4 修的是现有基准测不出的真实精度损失；1.5 会改变分段，因此**会**改变交付文本，方向上应当变好（切口落在静音、块更长、上下文更多），但在拿到端侧或带标注的对照基准之前，这是有依据的预期而不是已验证的结论。
