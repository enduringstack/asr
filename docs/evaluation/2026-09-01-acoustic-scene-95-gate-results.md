# 声音场景 95% 发布门禁结果（v4）

日期：2026-09-01

## 结论

纯音频方案仍未达到发布门禁，当前 App 的 7.24 MB、16 kHz DyMN04 模型没有被新实验权重替换，盲测集也没有运行预测。真实来源隔离校准集上，最强的 CLAP + AudioSet/DyMN 教师特征融合为准确率 **77.71%**、宏召回率 **77.11%**，两项都低于 95%。该结果是 Mac 上的教师特征实验，不是可直接部署到 HarmonyOS 手机的模型；v4 EfficientAT 实验使用官方 32 kHz 前端，在启用独立的手机 32 kHz 录音/FFT 分支前，打包脚本会拒绝复制不兼容模型。

因此本轮把产品路线拆成两个独立指标：

1. **纯音频指标**：只使用 30 秒连续音频，便于公开复现和衡量声学模型能力。
2. **系统融合指标**：在用户授权后融合 GNSS 速度、ASR 明确关键词和声音事件。融合结果必须用带同步传感器真值的手机实录数据单独验收，不能拿数据集标签伪造成速度或文本证据。

95% 门禁仍是准确率和宏召回率同时达到 95%，不通过删除困难“其他”样本、查看盲测后调参或混淆两套指标来达成。

## v4 数据协议

当前清单包含 2,275 个 32 kHz、10 秒窗口，来自 1,178 条原始录音和 960 个来源隔离组。训练、校准、盲测分别为 1,612 / 341 / 322 个窗口，对应 842 / 175 / 161 条原始录音。Radio Aporee 的每条长录音使用相邻的 0–10、10–20、20–30 秒窗口，运行和评分时按 `source_id` 平均 logits 后形成一个 30 秒决策；`source_group` 只用于防止同地点或同上传者跨集合泄漏。

Radio Aporee 共保留 549 条许可证审计后的实地录音，形成 1,646 个有效窗口。TAU/TUT 仍仅用于本地研究；App 可播放样本只选 CC0、Public Domain Mark 或 CC BY 的 Aporee 录音。普通列车、站外、咖啡厅附近等边界样本不会被方便地改成目标类别。

App 固定 Demo 为校准集每类 3 条、共 18 条连续 30 秒录音。每条可播放，并展示来源、许可证、真实标签、六类模型概率和是否匹配。它们不来自盲测集，可重复运行而不污染最终门禁。

## 校准集模型对比

| 方案 | 决策单位 | 准确率 | 宏召回率 | 状态 |
|---|---|---:|---:|---|
| DyMN20 32 kHz 六分类头 | 原始录音 | 64.00% | 61.91% | 端侧候选，失败 |
| AudioSet DyMN20 embedding + RBF | 原始录音 | 73.71% | 73.49% | 教师特征实验 |
| CLAP 零样本提示词 | 原始录音 | 50.29% | 61.25% | 失败 |
| CLAP + DyMN embedding + AudioSet tags + RBF | 原始录音 | **77.71%** | **77.11%** | 当前最佳，仍失败 |

最后一项逐类召回率为：地铁 97.4%、高铁 50.0%、商场 68.8%、咖啡厅/餐厅 76.2%、音乐现场 100%、其他 70.3%。高铁与地铁、商场与咖啡厅以及开放“其他”仍是主要错误来源。DCASE 2025 低复杂度声学场景官方结果中，严格未知设备设置的最佳系统准确率约 61.5%，也说明开放域纯音频任务并非接近通用 95% 的成熟问题。

## 已实现的系统融合

HarmonyOS 录音流程已加入可关闭的“上下文增强”：

- Location Kit 只在录音期间按需订阅；内存中只保留速度、速度精度和时间戳，不保存经纬度，结束、取消、异常和页面销毁都会停止订阅。
- 只有速度新鲜度不超过 15 秒、精度不差于 20 km/h 且速度达到 120 km/h 时，才把它作为高铁强证据；未授权、定位失败或低质量速度不会被解释成地铁。
- ASR 只在出现“高铁、动车、下一站、地铁、商场、咖啡、演唱会”等明确词语时提供有限加权；鼓掌/欢呼帮助音乐现场，餐具/切菜声帮助咖啡厅/餐厅。
- UI 同时显示“纯音频结果”和“融合结果”，并列出实际使用的证据，避免把上下文增强伪装成更强的声学模型。

融合代码已完成并通过主工程打包，但**尚未声明系统准确率达到 95%**。公开音频数据没有同步 GNSS 与手机 ASR 现场真值；下一阶段需要采集来源隔离的手机实录集，每类至少 100 条校准和 100 条盲测，并在采集时同步保存经用户同意的速度摘要。达到双 95% 前，不开启盲测、不替换 App 模型。
