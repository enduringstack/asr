# 端侧 ASR 中文真值评测设计

**状态：** 已确认，进入实现

## 目标与边界

在 HarmonyOS App 内提供一个固定的中文 ASR 评测入口，用 50 条带人工转写真值、可逐条播放的 AISHELL-1 test split 音频，检验当前产品最终转写模型，而不是用无文字真值的会议录音做主观判断。首期只回答干净近讲普通话的基础识别精度，不把结果解释为会议、车载、方言或强噪声能力。

固定集覆盖 AISHELL-1 test split 的 20 位说话人：每人至少 2 条，其中 10 人各增加 1 条；50 个句子互不重复。抽样过程固定随机种子、记录源文件路径和数据集修订，音频与真值随 App 打包，保证每次真机测试输入一致。AISHELL-2 受非商业科研和再分发约束，不进入 App；AISHELL-3 主要面向 TTS/声纹，AISHELL-4/5 分别作为未来会议和车载压力集，不与本次干净基线混算。

## 数据流与评分

评测页按顺序从 rawfile 读取 WAV，经现有 `StreamingSherpaWorker` 调用产品最终路径 `sherpa-onnx-paraformer-zh-2024-03-09/model.int8.onnx`，由手机现场返回原始 ASR 文本、音频时长与推理耗时。页面不读取历史预测，不根据文件名修正文本，也不调用网络服务。

参考文本与模型文本评分前统一做 Unicode 兼容范围内的全角转半角、英文小写化，并删除空白和标点；中文、数字及英文内容保留。Levenshtein 回溯分别统计替换、漏字和多字。单条展示真值、输出、CER 和三类错误；总体展示 micro-CER、macro-CER、完全正确率、失败数和 RTF。失败样本进入分母，防止加载或推理失败被隐藏。所有样本均可在非运行状态试听，并支持只看错误样本与单条重跑。

## 验收条件

1. App 固定显示 50 条 AISHELL-1 中文样本，20 位说话人且真值非空、句子不重复。
2. 每条可播放、可单独运行；批量运行由端侧模型逐条生成结果。
3. CER 算法有 ArkTS 单元测试，覆盖完全匹配、替换、删除、插入、标点和全角字符。
4. 页面显示模型身份、数据协议和所有汇总指标，错误样本可筛选。
5. ArkTS 测试、HAP 构建和真机增量安装通过；不卸载 App、不清除用户数据。
